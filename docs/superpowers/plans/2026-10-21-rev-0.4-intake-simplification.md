# Revision 0.4 Intake Simplification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply the owner's revision 0.4 feedback: string `case_id`, no `project_id`, optional
`offset_unit` that is reported back, optional `annotations` (a plain narrative is the default
submission), and minimal, foreign-field-free examples in the API documentation.

**Architecture:** The record contract lives in `config.py` (owned field names), `contracts.py`
(Pydantic schemas and shared adapters), and `validation.py` (pure checks). Reporting copies
`RecordResult` into `RecordObservation`. The changes stay inside those modules. Gate order,
wire decoding, the diagnostics machinery, and the response envelopes are unchanged.

**Tech Stack:** Python 3.14, FastAPI, Pydantic v2, pytest, ruff, mypy (strict).

**Spec:** `docs/scat-validation-endpoint-spec.md` (rev 0.3 → this plan updates it to rev 0.4).

## Product decisions (owner answers, 21 October 2026)

| Topic | Decision |
| --- | --- |
| `case_id` | Required JSON string `<case number>-<version>`: case number = ASCII letters/digits, optionally `.`/`_` inside (starts and ends with letter/digit); exactly one `-`; version = ASCII digits. 1–64 chars total. Kept exactly; compared as an exact string (`"5-01"` ≠ `"5-1"`). Number tokens fail `INVALID_TYPE` (no coercion). Empty/whitespace-only → `EMPTY_VALUE`; any other syntax failure → `INVALID_ID`. Example `"12345678-1"`. |
| `project_id` | No longer an owned field. If sent, it is ordinary foreign metadata: preserved, echoed, and inventoried; never validated. |
| Batch identity | `record_identity_uniqueness` checks that a valid `case_id` is unique within a batch. `DUPLICATE_RECORD` goes on later repeats. Repeats across requests stay allowed. |
| `offset_unit` | Optional. Absent → the server uses `unicode-code-point`. If supplied it must still be the string `unicode-code-point` (`INVALID_TYPE` / `INVALID_OFFSET_UNIT`); a wrong unit still skips range/text checks. No aliases and no case folding. Each `RecordObservation` gets `offset_unit`: `"unicode-code-point"` when absent or valid, `null` when the supplied value is invalid. The echo is **not** changed (spec §4.1 preservation). |
| `annotations` | Optional; a narrative with no annotations is the default submission. Absent → `annotation_count: 0`, `annotations_by_label: {}`, annotation checks pass vacuously, nothing inserted into echo. Explicit `null`/non-object still fails `INVALID_TYPE` (missing ≠ null stays a rule). Pre-existing annotations remain fully supported, since that support already exists. |
| Docs examples | OpenAPI request examples lead with the minimal record `{"case_id","username","narrative"}`, then an annotated record. Neither has foreign fields. `examples/valid-record.json` becomes that minimal record. The foreign-metadata reference record moves to `examples/metadata-record.json`. |

Required record fields are now `case_id`, `username`, `narrative`. Owned (non-foreign) record
fields are `case_id`, `username`, `narrative`, `offset_unit`, `annotations`, in that order for
diagnostics.

## Global Constraints

- Every rule in spec rev 0.3 not named above is unchanged (decoder, gates, numbers, Unicode, caps, budgets, echo exactness).
- No coercion, trimming, normalization, or inserted defaults in the source tree or echo.
- Fixed messages ≤ 256 UTF-8 bytes and never contain submitted values.
- `make check` (ruff format/lint, strict mypy, pytest) must pass after every task.
- Commits follow the existing conventional style (`feat(...)`, `test(...)`, `docs(...)`).

## Review Focus

1. `case_id` with a trailing newline (`"12345678-1\n"`) must fail `INVALID_ID`, because Python `$` would match before the newline. Use `fullmatch` and a Rust-regex Pydantic pattern. Test in Task 1.
2. Legacy numeric `case_id` (`5001`) → one `INVALID_TYPE`, observation `case_id: null`, and the uniqueness check skipped. Test in Task 1.
3. Old payload still carrying `project_id: 0`: valid, with `/project_id` in the inventory. Test in Task 1.
4. `offset_unit` supplied as `null` → `INVALID_TYPE`, ranges skipped, observation `offset_unit: null`. Test in Task 2.
5. Minimal record with `?echo=true` echoes exactly the three fields, with no `offset_unit`/`annotations` inserted. Test in Task 2.
